# 节点搜索增量加载设计

## 背景

节点搜索目前一次请求并渲染 100 条结果。节点目录较多时，初次搜索和前端渲染都偏重；下拉菜单中的长文件名连续换行，还会与后续 Negative、Width 等表单控件产生视觉拥挤。

## 目标

- 首屏只加载少量节点。
- 用户滚动接近列表底部时自动加载下一页。
- 搜索下拉保持浮层，不推动后续表单发生布局跳动。
- 长节点名称保持单行并使用省略号。
- 保留现有模糊搜索、防抖、选中、清除和关闭行为。

## 接口设计

`GET /api/nodes` 增加 `offset` 参数，继续使用 `limit` 控制页大小：

```text
/api/nodes?role=character&q=homura&offset=0&limit=20
```

响应结构增加分页信息：

```json
{
  "schema": "tags-machine-core.web.node-list/v1",
  "role": "character",
  "nodes": [],
  "offset": 0,
  "limit": 20,
  "has_more": true
}
```

后端遍历匹配节点时跳过 `offset` 条，收集 `limit + 1` 条。多出的一条仅用于计算 `has_more`，不会返回给前端。`offset` 最小为 0，`limit` 继续限制在 1 到 500。

本阶段不建立全量节点缓存，避免外部工具修改 `design` 后产生缓存过期。后续页面会重新扫描前缀，但常见节点选择只浏览前几页，优先保持实现和数据一致性简单可靠。

## 前端状态

每页固定加载 20 条。`NodePicker` 维护：

- 当前结果 `nodes`。
- 当前查询词 `query`。
- 下一页偏移量 `nextOffset`。
- 是否还有下一页 `hasMore`。
- 首页加载状态 `loading`。
- 续页加载状态 `loadingMore`。
- 首页错误和续页错误。

搜索词或角色类型变化时：

1. 递增现有 `requestId`，废弃旧请求。
2. 清空旧结果和续页状态。
3. 从 `offset=0` 加载第一页。

续页结果按节点 `ref` 去重后追加。快速输入或关闭菜单后返回的旧请求不得更新状态。

## 滚动触发

在结果列表底部放置哨兵元素，使用 `IntersectionObserver` 观察哨兵是否进入下拉列表的可视区域。满足以下条件时请求下一页：

- 下拉菜单仍然打开。
- `hasMore` 为真。
- 当前没有首屏或续页请求。
- 当前没有续页错误。

续页错误显示在列表底部，并提供“重试”按钮，避免滚动观察器反复自动请求失败页面。

## 浮层样式

- 下拉列表继续使用绝对定位，不推动页面内容。
- 当前 Node Picker 聚焦时提高层级，确保菜单绘制在后续表单之上。
- 菜单左右略微扩展，遮住后续字段从边缘露出的文字。
- 结果项宽度占满菜单。
- 节点名称使用单行、溢出隐藏和省略号。
- 增加稳定行高和内边距，避免结果密集粘连。
- 菜单维持固定最大高度和纵向滚动。

## 状态展示

- 首页加载：列表主体显示“正在搜索”。
- 续页加载：列表底部显示“正在加载更多”。
- 已加载全部：不额外占用一整行，只停止观察和请求。
- 无结果：显示“没有匹配节点”。
- 续页失败：底部显示错误摘要和“重试”按钮，已加载结果仍可选择。

## 验收标准

- 首次请求使用 `offset=0&limit=20`，最多渲染 20 条结果。
- 滚动至底部后请求 `offset=20`，新结果追加而不是覆盖第一页。
- 多次滚动能够继续请求 `offset=40`、`60`。
- 搜索词变化后结果和偏移量重置，不混入旧关键词结果。
- 同一节点不会因分页边界重复出现。
- 下拉浮层完整遮住后续表单，长名称单行省略。
- 续页加载期间仍能选择已经加载的节点。
- API、组件测试、前端构建和真实浏览器滚动验收通过。
