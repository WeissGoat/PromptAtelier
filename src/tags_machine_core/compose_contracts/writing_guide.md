## 首次编写流程

主 Agent 读要求和素材，与用户讨论并确认方案。按目标格式读完对应提示词 Skill，再写契约计划区和正式帧。在有工具的环境运行 `contract check`，修正 error 并逐条审阅 warn。有状态变化规划时，用「提示词复核派单模板」交独立子 Agent 逐帧审查并回看整组。主 Agent 汇总覆盖、裁决疑点，按需修补和复核，交付契约正文以及单独的复核与裁决记录。写回文件时可填 `title` 和 `author`。

## 提示词修订与重出流程

**主 Agent 改词 → 提示词复核子 Agent 审查 → 主 Agent 修补 → 提示词复核子 Agent 复核最终版 → 通过后生图 → 图片复核子 Agent 审新图 → 有待修正的画面问题就带着证据回到「主 Agent 改词」，进入下一轮。** 图片复核确认原问题已解决且没有新的待修问题时，结束本轮，交用户挑图。

1. 主 Agent 修改后运行 `contract check`，审阅 warn，交提示词复核子 Agent 审查改动帧和衔接。没有状态变化规划也可以走这套流程；局部改词查相关帧，涉及跨帧状态再沿状态链扩大范围。
2. 主 Agent 根据证据修补或说明保留理由，把最终词版交回复核。子 Agent 检查原问题是否解决、有无新问题，给出该版本的结论和实际覆盖范围。初审无须改动时，可以直接给结论。
3. 正式出图通常安排在最终版复核通过后。讨论例图、小范围试图或暂时没有可用子 Agent 时，主 Agent 可按改动影响和现有授权决定先试图或交付待复核稿，并说明哪些检查还没做。工具校验、自检和旧版报告各有用途，不能记作当前版本的独立复核通过。
4. 图片复核子 Agent 打开新图和相邻帧，按上轮问题编号说明已解决、仍存在或待核实，另列新发现。主 Agent 默认只读文字报告，按帧号、画面证据和对应词块修订，带着问题编号及改动回到第 1 步。证据不足时，让图片复核子 Agent 补看指定帧。若只是个别候选不佳或生成失败，可换候选或按授权同词重试，并把新的候选交给图片复核子 Agent 检查。没有出图授权时交付改稿和待出图范围。

## 头脑风暴与方案确认

主 Agent 先读用户要求、已有契约与全组素材摘要，再分段读必要素材，在对话中提出创作方案。说明对要求的理解、整体走向、用序号列出的阶段安排、重要状态的保持与变化，以及素材如何使用、合并或补充。有实质分歧时给出可选择的方向和推荐，不为凑数量强行提供多个方案。没有叙事要求的任务可以只给简短的逐帧适配方案，不额外编造剧情。

用户确认方案后，才把确认内容落实成契约计划区并开始写正式帧。新建契约、复制要求 prompt、已有计划文本都不等于用户确认。会话中已经明确确认且仍适用的方案直接沿用，不重复索取确认；用户提出修改时先修订方案，未收到确认前停留在讨论阶段。

正式写作中的一般措辞、构图优化由主 Agent 自行处理；需要改变已确认的剧情方向、重要状态走向或用户要求时，先向用户说明并确认调整。对已有契约的局部修正沿用已确认方案，不重新发起整组头脑风暴。用户要求讨论例图时，可在其指定画风与范围内准备少量明确标为草稿的代表帧，不因此扩展为正式整组写作。

## 计划区

在 front matter 之后、第一帧之前写确认后的自然语言计划，并纳入讨论中已接受的修改。计划不提交生图，不需要状态机、固定字段或逐帧变化点。简单任务可以简写；没有叙事要求时，仍按动作组原顺序一个成员一帧。

计划区使用以下三级标题；不要用二级标题，`##` 留给正式帧：

### 用户自定义要求

原样保留请求中的定制要求；没有则写“无”。用引用块保留原文（每行加 `> `），避免用户原文中的标题被识别为帧。用户要求优先，Agent 推导出的安排在下面单独说明。

### 全局要求

整理整组目标、共同设定和必须遵守的要求，区分用户明确要求与 Agent 的理解、补充安排。

### 阶段安排

用 `1.`、`2.`、`3.` 等序号描述阶段及其衔接，不必指定帧号。简单任务可以只有一个阶段。
按素材和定制要求安排；`keep_order: true` 时保持动作组顺序，`false` 时可按叙事重排。合并或舍弃成员时在相关帧备注说明；新增过渡帧仍遵守 `allow_new_frames` 和 `max_new_frames`。

### 状态变化规划

有需要持续保持或发生变化的状态时再写这一节。例如：服装、表情、道具、背景等。维度按本契约选择，可以增减，不强制包含这些例子；描述保持、变化和衔接的逻辑，不必落实到具体帧。

区分事实状态与可见描写：镜头外、提示词未明确、明确改变是不同情况，没写不等于消失。情绪基调允许不同的具体表情；背景元素按当前景别、裁剪和视觉焦点取舍，用户明确要求入镜的内容应保留。

## 写提示词前必读的 Skill

写正式帧提示词或改写已有提示词前，按契约的 `target_format` 完整阅读对应 Skill 入口，再按入口要求读完必读参考资料和本次写词所需章节；只看到技能名、简介或截断片段不算读完。会话中已读完且仍适用的内容可以沿用，无需每帧重复阅读。

| 目标格式 | Skill 与阅读要求 |
|---|---|
| `nai-v4.5` | `nai45-prompt`：读完入口及其指定的必读语法、实践资料，并阅读最接近本次任务的例子 |
| `nai-v5`、`nai-v5-curated` | `nai5-prompting`：读完入口及其指向的本次任务所需方法；已有确认方案则接续对应写词阶段 |

按 Skill 名称自行查找：先查看当前可用技能列表及其入口；未列出时，再在项目和环境提供的技能位置搜索同名 Skill，不依赖固定安装路径。找到后按其入口解析参考资料位置，不复制其正文或另建替代版本。查找后仍不存在或无法读取时，再向用户反馈缺少的 Skill 名称、已查位置及读取问题，请求可用入口或所需正文；阅读完成后再写该格式的正式提示词，不能声称已读。其他目标格式沿用其相应规范，不套用不适用的模型语法。

将 Skill 中的语言、权重、角色分块及动作表达方法用于契约。契约仍采用本项目 Markdown 帧格式；画师、质量词和生图参数由画风 / renderer 处理，不因外部 Skill 的默认值覆盖用户要求、已确认方案或契约边界。按相应 Skill 适用的自检要求检查，最终仍运行 `contract check`。

## 提示词编写原则

- 每帧自主拼出完整提示词，结合素材的 `clothing_state`、`character_scope`、构图和用户要求取舍。
- 出现的角色保留身份锚点。身份词应符合可见范围：背影、头部出画时使用角色名、发色、服装或标志物等适合镜头的词，避免用必须露脸的瞳色、眼神词迫使人物转头。
- 优先保留动作核心；素材中的状态、环境或角色词与用户要求及本帧安排冲突时，由 Agent 改写。尽量沿用原词写法，便于 Web 标记来源，需要时可调整权重。
- 状态应前后衔接，变化应有上下文依据；相邻帧应有有意义的区别，有意保留相似帧时在备注中说明。
- 多角色按目标格式用分角色代码块；动作中的人物对应以定制要求为准。
- 新增帧用 `source: custom`，参考动作写入 `inspired_by`。帧 id 用于回挂结果，修改提示词时保持稳定。
- 权重、语言和长度遵守目标格式。不要写画师名、质量前缀或生图参数；不要修改素材源节点或 front matter 的请求部分。

## 复核的质检立场与证据要求

复核子 Agent 的职责是找出并核实缺陷。接单时先假设本轮材料存在问题，从最可能出错的帧、词块或画面局部入手，尝试推翻“状态连续、动作成立、符合用户要求”的判断。实质性疑点要能说清哪一帧的什么细节值得怀疑、为什么，以及用什么证据核验。

按实际材料核实：提示词复核引用具体正负词与前后帧；图片复核先观察可见事实，再对照计划和词，检查动作与空间关系能否成立、人物与物件接触是否合理、身份服装道具是否穿帮、背景是否破坏连续性或预期裁剪。计划没有写的可见问题同样报告；不能用“艺术处理”“情绪升华”“整体不错”替代核实或替主 Agent 开脱。

严禁用“极佳”“优秀”“完美”“天衣无缝”等空洞赞美、打分或鉴赏性段落充当质检。推荐保留某帧或候选时，说明解决了哪个问题、哪项具体事实成立及仍有何局限。无明显问题的逐帧行也写实际检查到的事实与比较对象。

发现疑点先核实，再定性：图片应打开对应和前后帧原图，必要时比较同帧候选；检查机位、遮挡或自然动作能否解释变化。无法核实则标为待核实，并说明缺什么证据。严苛不等于编造错误，不设必须找出几个问题的配额；“暂未发现明确缺陷”只能用于实际检查过的范围，并说明检查依据、未覆盖内容及剩余不确定性，不能扩写为“全组通过”。

先列按影响排序的问题，再附逐帧证据、整组回看和覆盖说明。每个问题至少包含：问题 id、严重程度（阻断 / 重要 / 轻微）及证据状态（明确 / 疑似 / 待核实）、帧号与图片路径 / 提示词位置、观察事实及前后对照、对用户目标或连续性的影响、处理建议和不确定项。例如，提示词复核可指出“f46 的 c1 正向块又写入外套，和 f45 已脱下的状态冲突”；图片复核则需要指出“f46 原图确实画出了外套，f45 原图未穿”，并附图片定位。两种证据不能互相替代。

主 Agent 验收时查找报告实际追查的疑点及其证据。全篇没有提出实质性疑点，直接判定本次复核无效，退回补查。照抄清单、模板例子或每帧填“正常”均不算提出疑点。疑点经核验全部排除时，保留最值得追查的一项及其排除依据，可以据此报告“在已查范围未发现明确缺陷”。主 Agent 决定保留某项时也应回应证据，不能事后改计划为穿帮开脱。

## 红线质检清单（最小检查维度）

以下四项是复核的检查下限，不依赖计划是否列出相关状态，不替代身份、服装、表情和其他已约定的检查。提示词复核检查表达中的矛盾与风险；图片复核必须据实际画面核实，不能以词写对了认定图也正确。该清单只规范检查，不新增契约必填状态字段。

### 【机位与视线穿帮排查】

- 核实正背面、俯仰视角、镜头方向、人物朝向和实际可见部位能否同时成立，有没有为了露脸强行扭头、背面镜头却错误露出正面特征等问题。
- 核实视线实际指向谁或什么，与头部方向、互动对象和前后镜头是否衔接；不要将看向镜头、看向对方、看向物件混为一谈。
- 对照前后帧的空间关系，排查无依据的左右关系反转、视线目标跳变、遮挡或透视矛盾；先排除合理换机位、反打和裁剪，不能只因屏幕左右改变就判穿帮。

### 【道具与环境连续性排查】

- 核实道具的有无、数量、外观、佩戴或持有者、位置及使用状态；变化是否有上下文依据，有无凭空出现、消失、换手、复原或复制。
- 核实场景、主要陈设、光线以及人物与环境的空间关系是否前后合理；区分实际跳变和镜头外、遮挡、虚化或合理省略。
- 同时检查无用背景元素是否抢占焦点、遮挡主体、拉远景别或破坏目标裁剪，给出具体元素及影响，不要求每帧堆满背景。

### 【用户负面禁令排查】

- 从原始用户要求和会话中的有效补充提取明确的“不要 / 禁止 / 避免”及其作用范围，引用原文逐条核对；不能只依赖主 Agent 整理的计划，以免遗漏。用户没有提出的限制不自行升级为禁令；未提供明确禁令时注明这一事实。
- 逐帧检查适用禁令是否被正向或分角色提示词带回，或已在实际画面中出现；例如用户禁止看向镜头、某种表情或某物时，要核实具体表现，而不是确认已写进负面词就算完成。
- 区分用户禁令、负面提示词的抑制意图和正向 / 画面事实；不能因禁用词出现在 negative 块就判违规。明确违反有效禁令的标为阻断项交主 Agent 裁决，不以其他优点抵消；图中看不清时标待核实，不能默认符合。

### 【姿势物理逻辑排查】

- 核实站、坐、跪、躺及过渡动作：重心、支撑点、脚与地面、臀部与座面等接触是否成立；有无无支撑悬空、坐姿未落座、姿势无依据反复。
- 核实肢体连接、关节朝向和活动范围，人物与人物 / 道具的接触、抓握、遮挡和受力是否合理，有无穿透、断接或无法完成所述动作的姿态。
- 结合机位、遮挡、动作阶段和用户允许的表现方式判断；缺乏可见证据时不强推姿势，不把合理的夸张表达一概判错，也不以“艺术处理”掩盖明确的接触与支撑矛盾。

逐帧表需覆盖四项结果，可在原表中追加四个简短栏目或在同一行逐项注明，无需重复四份大表。每项标“未见明确缺陷 / 发现问题 / 待核实 / 不适用”，并附简短事实或不适用原因；发现问题时关联问题 id。仅打勾、写“正常”、漏项或凭计划推断通过都不算检查完成。图片问题仍须提供原图和前后帧依据；主 Agent 验收逐帧及分段报告时核对四项覆盖，遗漏则退回补查。

## 提示词复核

只要写了状态变化规划，主 Agent 写完提示词后就安排独立的提示词复核子 Agent。提供原始用户要求、完整计划、全部帧的最终正负提示词（含分角色块）和备注，必要时提供来源素材。子 Agent 只报告提示词的实际表达、冲突和可能风险，不据此断言图片会怎样或已经怎样。

子 Agent 必须覆盖每一帧，逐帧列出相关维度的状态并分析，即使没有问题也要有一行。建议表格：

| 帧 | 对应阶段 | 本帧各项状态及提示词依据 | 与前后文的变化、分析及疑点 |
|---|---|---|---|

维度随计划选择。从最终提示词提取实际表达，不把计划复制成检查结果；区分明确描写、镜头外、未明确和根据上下文推断的持续状态。阶段不明时注明不确定，不强行分配。

重点检查状态跳变或回退、遗漏必要过渡、素材残留词与安排冲突、背景描写与裁剪冲突；表情变化是否合理应结合基调和互动判断。发现计划未覆盖的重要维度可提醒主 Agent 补充，不自行扩大约束。

长契约可以分段复核，每段都带完整计划和相邻上下文；最终按契约顺序汇总所有帧（包括插入帧），报告覆盖范围和数量，不用抽样或“其余正常”代替逐帧分析。疑点给出帧号、提示词依据及计划或上下文依据，区分明确冲突、疑似问题和信息不足。

逐帧分析之后，再按计划中的各个维度纵向回看整组，概括状态如何保持和演变，寻找相隔多帧才出现的回退、跳变，以及阶段转折和分段交界的问题。汇总整组发现和依据即可，不必再复制一张大表；仅检查相邻帧不能替代这一步。

主 Agent 对每个疑点作出修改、保留并解释或澄清计划的裁决，原始用户要求和已确认方案优先。改词后按「提示词修订与重出流程」安排复核；涉及改变已确认方案的重要方向时，先按前述方案确认流程处理。完整逐帧报告、整组回看和裁决记录在对话或单独报告中交付，不附在最后一帧后面。

若执行环境不支持子 Agent，明确说明尚未完成独立复核；主 Agent 的自检不能冒充子 Agent 复核。可以交付草稿和自检记录，由支持子 Agent 的环境接续复核。

完成时检查：契约计划与帧已写好，`contract check` 无 error，warn 已审阅；有状态变化规划时，独立复核覆盖全部帧、主 Agent 已处理全部疑点，再将 `status` 改为 `done`。草稿仍可保留 `pending`。Web 导入后的 `done` 只是文件状态，不证明独立复核已经完成。

## 出图后的图片复核

进入图片复核阶段，由独立、具备看图能力的子 Agent 实际打开图片检查。主 Agent 提供原始要求、已确认计划、对应最终提示词、图片路径与结果信息，并指定契约版本、画风、轮次和帧范围。旧图与当前提示词的图分别标明，不混用结论。使用 `compose-contract-review` Skill 的联系表和元数据工具；`contract review --sheets` 生成的是检查材料，不等于已经完成视觉复核。

图片复核同时检查两件事：是否符合用户要求和计划，以及实际图片自身能否前后连贯。后者独立于主 Agent 的计划和状态维度；即使没有状态变化规划，或计划未提到某项，也要根据画面发现生成不稳定导致的姿势、位置、朝向、人物与物体关系等变化。例如前帧坐在椅上，后帧突然站立，再下一帧又坐回，不能仅以“计划未规定姿势”忽略疑点。

先看按帧排列的联系表，从图片提取每帧实际可见状态，分析相邻帧及整段的动作和空间衔接，再对照要求、计划和提示词。打开可疑帧及前后帧原图核实，必要时比较同帧候选。报告将“图片实际呈现及连续性依据”与“计划 / 提示词预期”分开，标明问题涉及的前后帧和图片路径；未写入计划的视觉疑点同样交主 Agent 裁决。

背景元素需同时检查连贯性与构图适用性：场景、主要陈设及其与人物的空间关系是否前后合理，有没有无依据地出现、消失或换位；当前帧是否出现对叙事或视觉焦点无帮助的背景元素，抢占画面、遮挡主体、拉远景别或造成不合适的裁剪。结合实际机位与景别判断，不要求每帧呈现全部陈设；合理出画、虚化或省略不算背景不连续。报告指出具体背景元素、视觉影响及建议，交主 Agent 决定是否精简背景提示词、调整构图、换候选或重出。

区分合理动作变化、镜头切换、裁剪造成的不可见与无依据的跳变，不要求相邻帧姿势完全相同，也不强迫每次自然变化都增加过渡帧。下半身出画时不能凭半身像断定站立或坐下；图片未展示或无法辨认的内容标为不确定，不用提示词补成视觉事实。

子 Agent 报告看过的帧与图片、问题依据和候选建议，区分提示词可能存在的问题、个别候选表现不佳，以及缺图、失败或只有旧图；不能只因候选都没画对就断言提示词有错。主 Agent 决定推荐候选、调整提示词或重出，最终采用由用户选择。契约修改和生成任务由主 Agent 统一执行，沿用用户已授权的画风和范围，重出后检查相关帧及衔接。

联系表和原图默认由图片复核子 Agent 打开，包括讨论例图、首次出图和重出的候选。主 Agent 准备图片路径、阅读报告并裁决。没有可用的看图子 Agent 时，标明待视觉复核。若用户指定主 Agent 看图，或确需由其核实某个局部，限于相关帧，将观察单独注明为主 Agent 自检。

## 子 Agent 的委派与管理

主 Agent 统一负责用户沟通、方案确认、契约修改、生成任务和最终裁决。头脑风暴由主 Agent 与用户完成，不固定增加第三类子 Agent。

| 职责 | 介入时机 | 输入与交付 |
|---|---|---|
| 提示词复核 | 首次写完且有状态变化规划；或按修订流程复核改动时 | 原始要求、确认后计划、当前提示词与备注；初次整组复核交逐帧分析和整组回看，修订交受影响范围及当前版本结论 |
| 图片复核 | 出图后进入图片复核阶段，有无状态规划均适用 | 上述依据及实际图片、结果信息；独立分析实际画面连续性并对照计划，交付看图结论、疑点和候选建议 |

主 Agent 选择相应模板，填写方括号并附上接收方能打开的材料。共享文件可给路径，跨环境时附上文字和图片。初审和复核使用同一份角色模板，复核时补上上轮问题和本轮改动。

### 提示词复核派单模板

```text
你是提示词复核子 Agent。只读检查最终正负提示词和分角色块，向主 Agent 报告表达冲突或生成风险。修改、派单和生图由主 Agent 负责。

带着“恶意挑刺”的眼光审词。先假设这版提示词藏着逻辑硬伤，从最可能画错的一处往回查。比如角色的同一只手是否被写成同时支地和举杯，或用户禁用的道具是否又被角色正向词带回。用本次任务的具体帧号、正负词块和前后文核验，说明冲突成立、已排除，还是缺少依据。严禁使用“极佳”“优秀”“完美”“天衣无缝”等空洞赞美。全篇没有提出实质性疑点，本次复核无效。若疑点全部排除，写出最可疑的一处及排除它的具体词句。

本次检查 [契约 id / 当前版本]，范围 [帧号，含衔接帧]，任务 [初审或改词后复核]。
材料包括 [用户原始要求及补充、确认的计划、最终正负词与备注]。改词后复核另附 [上轮问题编号与依据、改了哪些帧、主 Agent 的处理理由]。若问题来自审片，按文字报告追查这次词块改动是否回应了画面缺陷，处理效果交下一轮图片复核验证。

逐帧从实际词块提取计划中的状态，分析与前后帧的衔接。查四项红线：机位与视线能否同时成立，道具与环境连续性是否被词块破坏，用户负面禁令是否被正向词带回，姿势物理逻辑是否矛盾。引用适用的用户禁令，区分正向要求与负面词的抑制作用。初审按维度回看整段或整组，查远帧回退。复核追查原问题和新引入的风险，范围随改动影响调整。

例如 f45 和 f47 的 c1 块都有眼罩，f46 漏写，可报告“f46 有掉道具风险”。这个结论只说明词块表达了什么。
报告开头写角色、版本和实际覆盖。先列问题，附编号、严重程度、证据把握、帧号、词块原文及前后对照、影响和建议。再逐帧简记各项状态、四项红线的结果和依据，说明未能核实或不适用的原因。明确违反用户禁令的标为阻断。给出本版结论与剩余疑点，有无问题都以证据为准。
```

### 图片复核派单模板

```text
你是图片复核子 Agent。实际打开本轮图片，独立找穿帮，向主 Agent 提交只读审片报告。主 Agent 裁决和执行修改或重出，用户最终选图。

带着“恶意挑刺”的眼光审片。先假设画面存在缺陷，专找逻辑硬伤、穿帮、肢体或物体形变，以及违反用户要求的道具。锁定可疑部位后放大原图，对照前后帧，核实遮挡、透视或换机位能否解释异常。报告写明哪张图、哪个部位、为什么可疑、对照后看到什么。严禁使用“极佳”“优秀”“完美”“天衣无缝”等空洞赞美。全篇没有提出实质性疑点，本次复核无效。若疑点全部排除，写出最可疑的一处及排除它的画面证据。

本次检查 [契约 id / 词版、画风、生成轮次]，范围 [帧号、候选及衔接帧]，任务 [初审或重出后复核]。
材料包括 [联系表和可打开的原图、结果信息、用户原始要求及补充、计划、对应的最终词块]。重出后复核另附 [上轮问题编号、改动摘要、重出的帧和候选]。主 Agent 默认依据你的文字报告改词。说明哪个人物或道具、在画面什么位置、相较哪一帧发生了什么变化。逐项交代上轮问题是否解决，把仍存在的问题和新发现交回主 Agent 开始下一轮。

先按顺序看联系表，逐帧记录可见状态，比较相邻帧并回看整段。对疑点打开该帧及前后帧原图，必要时比较同帧候选。检查机位与视线、道具与环境连续性、用户负面禁令、姿势物理逻辑。独立寻找计划没写的跳变、近乎重复的相邻帧，以及抢焦点、遮挡主体或影响裁剪的背景元素。再对照计划、提示词和用户禁令原文。重出后核实原问题是否改善，有没有新的穿帮。

例如 f45 和 f47 都戴眼罩，若 f46 原图中双眼清晰可见且未戴眼罩，可定位为可见的道具中断。若 f46 只拍到下半张脸，则记“眼部出画，本帧无法核实”。
报告开头写角色、词版、画风、轮次和实际覆盖。先列问题，附编号、严重程度、证据把握、帧号、图片路径或附件名、画面局部与前后对照、影响和建议。再逐帧简记四项红线结果和依据，将画面事实与计划预期分开。缺图、只有旧图、遮挡或看不清时标明限制，明确违反用户禁令的标为阻断。无明确缺陷时给出观察依据，避免赞美性评价。
```

主 Agent 按上文「复核的质检立场与证据要求」验收实质性疑点、逐帧覆盖及核验依据。用旧图、词块或计划代替本轮画面证据时，退回补查。

两类子 Agent 均只读并返回报告，不再次委派、不修改契约、不提交生成任务、不操作采用标记；由主 Agent 汇总裁决。可复用已有子 Agent，每次重新声明角色、版本、范围和依据；切换角色时，前一轮报告只作线索，本次结论须由本次材料独立支持。

长契约可分段委派，每段携带完整计划、相邻上下文及所需素材；主 Agent 记录任务和覆盖范围，等待报告，补查遗漏、阶段转折和分段交界后汇总。失败或未完成的任务标明尚未覆盖，不能以“已派发”替代完成。修改后只补查受影响部分及衔接，旧版报告不作为当前版本已通过的证明。

以上是外部 Agent 的执行规范；当前 Web 仍通过复制要求 prompt 手动交接，没有自动启动或调度主、子 Agent 的功能。
